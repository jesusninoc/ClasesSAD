# Implantación de técnicas de acceso remoto. VPNs (Virtual Private Networks)

## Introducción

Las **redes privadas virtuales o VPN (Virtual Private Networks)** permiten establecer comunicaciones protegidas a través de redes que no están bajo el control directo de la organización, como Internet.

Una VPN crea un mecanismo mediante el cual dos extremos pueden comunicarse de forma protegida.

Un escenario sencillo sería:

```text
             INTERNET
        RED PÚBLICA / NO CONFIABLE
                  |
          +-------+-------+
          |               |
          v               v
       Usuario          Empresa
          |               |
          +------ VPN ----+
```

Desde el punto de vista del usuario, la VPN puede proporcionar la sensación de estar conectado a la red remota aunque físicamente se encuentre en otra ubicación.

Las VPN se utilizan habitualmente para:

- Acceso remoto de usuarios.
- Interconexión de sedes.
- Acceso seguro a servicios corporativos.
- Comunicaciones entre redes.
- Protección de determinadas comunicaciones.
- Conexión de trabajadores remotos.
- Conexión de infraestructuras distribuidas.

Una VPN no debe entenderse únicamente como un mecanismo de cifrado. En una implantación real intervienen diferentes elementos:

- Túneles.
- Cifrado.
- Autenticación.
- Autorización.
- Direccionamiento.
- Rutas.
- Protocolos.
- Servidores.
- Clientes.
- Sistemas de autenticación.

# 1. Redes privadas virtuales. VPN. Elementos de una VPN

## Resumen de conceptos

En este apartado se estudiará:

- Qué es una VPN.
- Red privada virtual.
- Túnel.
- Cliente VPN.
- Servidor VPN.
- Gateway VPN.
- Autenticación.
- Cifrado.
- Integridad.
- Direccionamiento.
- Rutas.
- Recursos remotos.

## Desarrollo teórico

Una **VPN (Virtual Private Network)** es una tecnología que permite establecer una comunicación protegida entre dos o más extremos utilizando una infraestructura de red compartida o pública.

En lugar de establecer una comunicación directa sin protección:

```text
Cliente ----------------------> Servidor
```

se establece una comunicación mediante un túnel VPN:

```text
Cliente
   |
   |========= TÚNEL VPN =========|
   |                             |
   v                             v
Internet                      Servidor VPN
                                  |
                                  v
                           Red corporativa
```

El túnel VPN permite transportar tráfico entre los extremos utilizando mecanismos de seguridad adecuados para la tecnología empleada.

---

## 1.1. Elementos de una VPN

Una solución VPN puede estar formada por diferentes componentes.

### Cliente VPN

Es el sistema que inicia o participa en la conexión VPN.

Puede ser:

- Un ordenador.
- Un teléfono.
- Una tableta.
- Un router.
- Un firewall.
- Otro dispositivo de red.

```text
Usuario
   |
   v
Cliente VPN
   |
   v
Internet
```

### Servidor VPN

Es el sistema encargado de aceptar y gestionar conexiones VPN.

```text
Cliente VPN
     |
  Internet
     |
     v
Servidor VPN
     |
     v
Red corporativa
```

### Gateway VPN

En determinadas arquitecturas, el dispositivo VPN actúa como puerta de enlace entre diferentes redes.

```text
Red A
  |
  v
Gateway VPN
  |
  |==== TÚNEL ====|
  |
  v
Gateway VPN
  |
  v
Red B
```

### Túnel

El túnel representa el canal lógico mediante el cual se transportan las comunicaciones entre los extremos VPN.

```text
EXTREMO A
    |
    |====================|
    |    TÚNEL VPN       |
    |====================|
                         |
                      EXTREMO B
```

### Autenticación

Permite comprobar la identidad de los usuarios o dispositivos que intentan establecer la conexión.

### Cifrado

Protege la confidencialidad de los datos frente a terceros que puedan observar la comunicación.

### Integridad

Permite detectar modificaciones no autorizadas de los datos durante el transporte.

### Direccionamiento

La VPN puede proporcionar al cliente una dirección IP o establecer rutas que permitan acceder a las redes remotas.

Por ejemplo:

```text
Cliente
IP local:       192.168.1.20

VPN
IP asignada:    10.10.10.25
```

### Rutas

Las rutas determinan qué tráfico debe enviarse a través de la VPN.

Por ejemplo:

```text
Red local:
192.168.1.0/24

Red corporativa:
10.10.0.0/16

Tráfico hacia 10.10.0.0/16
        |
        v
      VPN
```

# 2. Beneficios y desventajas con respecto a las líneas dedicadas

## Resumen de conceptos

Se estudiará:

- Líneas dedicadas.
- Internet.
- Coste.
- Flexibilidad.
- Escalabilidad.
- Seguridad.
- Rendimiento.
- Disponibilidad.
- Dependencia de Internet.

## Desarrollo teórico

Antes de la utilización generalizada de determinadas tecnologías VPN sobre Internet, las organizaciones podían utilizar **líneas dedicadas** para conectar diferentes ubicaciones.

Por ejemplo:

```text
SEDE A ========================== SEDE B
             LÍNEA DEDICADA
```

Una VPN permite utilizar una infraestructura compartida como Internet:

```text
SEDE A
   |
   v
INTERNET
   |
   v
SEDE B
```

La VPN establece un canal protegido sobre esa infraestructura.

---

## 2.1. Beneficios de las VPN

### Coste

Una VPN puede evitar la necesidad de contratar determinadas conexiones dedicadas exclusivamente para conectar dos ubicaciones.

El coste concreto dependerá de:

- Proveedor.
- Ancho de banda.
- Número de usuarios.
- Número de sedes.
- Tecnología VPN.
- Equipamiento.

### Flexibilidad

Una VPN puede permitir conectar usuarios desde diferentes ubicaciones.

```text
             VPN
        /      |      \
       /       |       \
 Usuario A  Usuario B  Usuario C
```

### Movilidad

Los usuarios pueden conectarse desde:

- Casa.
- Hoteles.
- Aeropuertos.
- Oficinas externas.
- Otras ubicaciones.

Siempre que dispongan de conectividad y autorización.

### Escalabilidad

Una organización puede añadir nuevos usuarios o sedes sin tener que establecer necesariamente una nueva línea física dedicada entre cada ubicación.

---

## 2.2. Desventajas de las VPN

### Dependencia de Internet

Una VPN que utiliza Internet depende de la conectividad disponible.

```text
Usuario
   |
   X
Internet no disponible
   |
   X
VPN no disponible
```

### Rendimiento variable

El rendimiento puede depender de:

- Ancho de banda.
- Latencia.
- Congestión.
- Calidad de las conexiones.
- Distancia entre extremos.

### Configuración

Una VPN puede requerir una configuración más compleja que una conexión convencional.

### Gestión de credenciales

Las organizaciones deben gestionar correctamente:

- Usuarios.
- Contraseñas.
- Certificados.
- Claves.
- Dispositivos autorizados.

### Seguridad

Una VPN correctamente cifrada protege la comunicación, pero no convierte automáticamente en seguros todos los sistemas accesibles a través de ella.

Por ejemplo:

```text
VPN
 |
 v
Red corporativa
 |
 +---- Servidor vulnerable
 |
 +---- Equipo comprometido
```

La seguridad de los sistemas internos sigue siendo necesaria.

## Resumen de conceptos

- Punto a punto.
- Dos extremos.
- Túnel.
- Comunicación entre dispositivos.
- Conexión permanente o bajo demanda.

## Desarrollo teórico

Una VPN punto a punto establece una comunicación protegida entre dos extremos.

```text
Extremo A
    |
    |========= VPN =========|
    |                       |
    v                       v
Extremo A                 Extremo B
```

Puede utilizarse, por ejemplo, para establecer una comunicación entre dos dispositivos o gateways.

Cuando los extremos son redes completas, se puede utilizar una arquitectura LAN a LAN.

# 3.2. VPNs de acceso remoto (LAN a road warrior)

## Resumen de conceptos

Se estudiará:

- Acceso remoto.
- Road warrior.
- Cliente VPN.
- Usuario remoto.
- Servidor VPN.
- Autenticación.
- Acceso a recursos corporativos.

## Desarrollo teórico

El modelo **road warrior** hace referencia a usuarios que necesitan acceder a los recursos corporativos desde ubicaciones externas.

```text
                  INTERNET
                      |
              +-------+-------+
              |               |
              v               v
        Usuario remoto     Usuario remoto
              |               |
              +-------+-------+
                      |
                     VPN
                      |
                      v
                 Servidor VPN
                      |
                      v
                RED CORPORATIVA
```

El usuario puede encontrarse físicamente fuera de la organización, pero establecer una conexión VPN para acceder a determinados recursos.

Por ejemplo:

```text
Trabajador remoto
       |
       v
      VPN
       |
       v
Servidor de archivos
```

El acceso debe estar limitado a los recursos necesarios.

No es obligatorio que un usuario conectado mediante VPN tenga acceso completo a toda la red.

## Desarrollo teórico

Una VPN LAN a LAN permite conectar dos redes mediante un túnel VPN.

```text
             INTERNET
                 |
       +---------+---------+
       |                   |
       v                   v
   Gateway A            Gateway B
```


# 4.1. PPTP (Point-to-Point Tunneling Protocol)

## Resumen de conceptos

Se estudiará:

- PPTP.
- Túnel.
- Acceso remoto.
- Tecnología histórica.
- Limitaciones de seguridad.

## Desarrollo teórico

**PPTP (Point-to-Point Tunneling Protocol)** fue utilizado históricamente para establecer conexiones VPN.

Permitía crear túneles para transportar determinadas comunicaciones.

```text
Cliente
   |
   |========= PPTP =========|
   |                        |
   v                        v
Internet                 Servidor VPN
```

Sin embargo, PPTP presenta importantes problemas de seguridad y **no debe utilizarse para nuevas implantaciones modernas**.

Su interés actual es principalmente:

- Histórico.
- Académico.
- Comprensión de la evolución de las tecnologías VPN.

Es importante que el alumnado conozca que no todas las tecnologías VPN antiguas deben seguir utilizándose simplemente porque aparezcan en documentación histórica.

# 4.2. IPsec (Internet Protocol Security)

## Resumen de conceptos

Se estudiará:

- IPsec.
- Seguridad a nivel de red.
- Autenticación.
- Integridad.
- Confidencialidad.
- Túneles.
- ESP.
- AH.
- IKE.

## Desarrollo teórico

**IPsec (Internet Protocol Security)** es un conjunto de protocolos y mecanismos destinados a proporcionar seguridad a las comunicaciones IP.

Puede proporcionar:

- Autenticación.
- Integridad.
- Confidencialidad.
- Protección frente a determinadas modificaciones de los paquetes.

IPsec puede utilizarse para conectar redes:

```text
LAN A
  |
  v
Gateway A
  |
  |========= IPsec =========|
                            |
                         Gateway B
                            |
                            v
                           LAN B
```

### ESP

**ESP (Encapsulating Security Payload)** proporciona mecanismos relacionados con la confidencialidad, integridad y autenticación de los datos, dependiendo de la configuración.

### AH

**AH (Authentication Header)** proporciona mecanismos de autenticación e integridad, pero no proporciona confidencialidad mediante cifrado.

### IKE

**IKE (Internet Key Exchange)** se utiliza para negociar determinados parámetros de seguridad y establecer asociaciones de seguridad.

# 4.3. IPsec/L2TP (Layer Two Tunneling Protocol)

## Resumen de conceptos

Se estudiará:

- L2TP.
- IPsec.
- Túnel.
- Acceso remoto.
- Separación de funciones.

## Desarrollo teórico

**L2TP (Layer 2 Tunneling Protocol)** permite crear túneles para transportar tráfico de capa 2.

L2TP por sí mismo no proporciona el conjunto de mecanismos de cifrado necesarios para proporcionar confidencialidad.

Por ello, históricamente se ha utilizado **L2TP/IPsec**:

```text
       L2TP
        |
        v
    Túnel L2
        |
        v
     IPsec
        |
        v
Protección de la comunicación
```

La combinación permite separar conceptualmente:

- L2TP para el túnel.
- IPsec para proporcionar mecanismos de seguridad.

# 4.4. SSL/TLS (Secure Sockets Layer / Transport Layer Security). OpenVPN

- SSL.

- OpenVPN.
- Certificados.
- Autenticación.

## Desarrollo teórico

**SSL (Secure Sockets Layer)** es una tecnología histórica que fue sustituida por **TLS (Transport Layer Security)**.

Por tanto, cuando se habla actualmente de comunicaciones seguras debe distinguirse entre:

```text
SSL
 |
 +---- Tecnología histórica

TLS
 |
 +---- Evolución utilizada actualmente
```

**OpenVPN** es una solución VPN que utiliza mecanismos basados en TLS para establecer comunicaciones protegidas.

Un esquema simplificado sería:

```text
Cliente OpenVPN
       |
       |====== TÚNEL ======|
       |                   |
       v                   v
    Internet           Servidor
                          |
                          v
                   Red corporativa
```

OpenVPN puede utilizar certificados y diferentes mecanismos de autenticación dependiendo de la configuración.

### Certificados digitales

Los certificados permiten asociar una identidad con una clave pública y facilitan mecanismos de autenticación basados en infraestructura de clave pública.

# 4.5. SSH (Secure Shell)

## Resumen de conceptos

- Túneles.
- Redirección de puertos.

## Desarrollo teórico

**SSH (Secure Shell)** es un protocolo diseñado para proporcionar comunicaciones seguras, especialmente para la administración remota de sistemas.

Su uso más habitual es:

```text
Cliente
   |
   | SSH
   v
Servidor
```

SSH proporciona:

- Confidencialidad.
- Integridad.
- Autenticación.

También puede utilizar mecanismos de túnel y redirección de puertos.

Por ejemplo:

```text

Servidor SSH

   | Túnel
   v
Servicio interno
```

Aunque SSH puede utilizarse para crear determinados túneles seguros, no debe confundirse con una solución VPN completa para conectar redes enteras.

### Desarrollo teórico

```text

               |
```
```text
               v
```


Los algoritmos simétricos suelen ser eficientes y resultan apropiados para proteger grandes cantidades de información.

# 15. Seguridad en la implantación de VPN

## Resumen de conceptos

Se estudiará:

- Mínimo privilegio.
- Autenticación fuerte.
- Cifrado.
- Certificados.
- Actualizaciones.
- Segmentación.
- Logs.
- Revocación.
- Monitorización.

## Desarrollo teórico

Una VPN no debe considerarse automáticamente segura simplemente por utilizar un túnel.

La seguridad depende de cómo se haya configurado.

### Utilizar protocolos adecuados

Debe evitarse el uso de tecnologías obsoletas cuando existan alternativas modernas.

### Utilizar autenticación adecuada

Cuando sea posible, deben utilizarse mecanismos robustos de autenticación.

### Proteger las credenciales

Las contraseñas, claves privadas y certificados deben almacenarse de forma segura.

### Aplicar mínimo privilegio

Un usuario VPN solamente debería poder acceder a los recursos que necesita.

### Mantener actualizado el servidor

El software VPN debe mantenerse actualizado.

### Registrar las conexiones

Los logs permiten conocer quién se conecta y detectar comportamientos anómalos.

### Revocar accesos

Cuando un usuario deja de necesitar acceso VPN, sus credenciales o certificados deben revocarse de acuerdo con el procedimiento de la organización.
