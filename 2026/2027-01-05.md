# Instalación y configuración de servidores «proxy»

## Introducción

Un **servidor proxy** es un sistema que actúa como intermediario entre un cliente y otro servidor.

En una comunicación directa, un cliente se conecta directamente con el servidor:

```text
Cliente ----------------------> Servidor
```

Cuando se utiliza un proxy, la comunicación pasa por un intermediario:

```text
Cliente ------------> Proxy ------------> Servidor
```

El proxy puede aplicar diferentes políticas sobre las comunicaciones.

Entre sus funciones se encuentran:

- Controlar el acceso a determinados recursos.
- Filtrar contenidos o solicitudes.
- Registrar la actividad.
- Aplicar políticas de seguridad.
- Realizar almacenamiento en caché.
- Aplicar mecanismos de autenticación.
- Controlar determinados tipos de tráfico.
- Actuar como intermediario entre clientes y servidores.
- En determinados escenarios, ocultar la dirección de los clientes frente a los servidores externos.

Los servidores proxy pueden utilizarse tanto en redes domésticas como en pequeñas empresas, organizaciones educativas o grandes infraestructuras corporativas.

Una arquitectura sencilla sería:

```text
                     INTERNET
                         |
                         v
                     [ PROXY ]
                         |
              +----------+----------+
              |          |          |
              v          v          v
             PC1        PC2        PC3
```

En este escenario, los equipos pueden utilizar el proxy para acceder a determinados servicios externos.

El proxy se convierte en un **punto de control de las comunicaciones**.

## 1.1. Proxy directo

### Resumen de conceptos

Se estudiará:

- Forward proxy.
- Cliente.
- Servidor externo.
- Intermediación.
- Red corporativa.
- Control de acceso.

### Desarrollo teórico

El **proxy directo**, denominado habitualmente **forward proxy**, se sitúa entre los clientes de una organización y los servidores externos.

```text
              RED CORPORATIVA

       +---------+---------+
       |         |         |
       v         v         v
      PC1       PC2       PC3
       \         |         /
        \        |        /
         +-------+-------+
                 |
                 v
              [ PROXY ]
                 |
                 v
              INTERNET
                 |
                 v
             SERVIDORES
```

En este modelo, los clientes utilizan el proxy para acceder a recursos externos.

El proxy puede aplicar políticas como:

- Permitir determinados sitios.
- Bloquear determinados destinos.
- Registrar las solicitudes.
- Solicitar autenticación.
- Aplicar límites de uso.
- Utilizar caché.

Es uno de los modelos más habituales cuando se pretende controlar la navegación de los usuarios de una organización.

---

## 1.2. Proxy inverso

### Resumen de conceptos

Se estudiará:

- Reverse proxy.
- Servidores.
- Clientes externos.
- Publicación de servicios.
- Intermediación.
- Protección de servidores.
- Distribución de tráfico.

### Desarrollo teórico

El **proxy inverso**, o **reverse proxy**, se sitúa delante de uno o varios servidores.

```text
                    INTERNET
                        |
                        v
                 [ REVERSE PROXY ]
                   /      |      \
                  /       |       \
                 v        v        v
              WEB 1     WEB 2    WEB 3
```

En este caso, los clientes externos no necesitan comunicarse directamente con los servidores internos.

El reverse proxy puede proporcionar funciones como:

- Intermediación.
- Control de acceso.
- Terminación de determinadas conexiones.
- Distribución de solicitudes.
- Registro.
- Protección de servidores.
- Integración con mecanismos de seguridad.

Una diferencia importante es:

> El **proxy directo** se sitúa principalmente entre los clientes y los servidores externos.

> El **proxy inverso** se sitúa principalmente entre los clientes externos y los servidores de una organización.

## 1.3. Proxy transparente

### Resumen de conceptos

Se explicará:

- Proxy transparente.
- Interceptación.
- Configuración del cliente.
- Redireccionamiento.
- Ventajas.
- Limitaciones.

### Desarrollo teórico

Un **proxy transparente** permite que determinados clientes utilicen el proxy sin necesidad de configurar manualmente el proxy en cada aplicación.

Conceptualmente:

```text
Cliente
   |
   | Solicitud
   v
Router / Firewall
   |
   | Redirección
   v
Proxy
   |
   v
Internet
```

La infraestructura de red puede redirigir determinados tráficos hacia el proxy.

Una de sus ventajas es simplificar la configuración de numerosos equipos.

Sin embargo, la utilización de un proxy transparente depende del tipo de tráfico y de la arquitectura utilizada.

## 1.4. Proxy explícito

### Resumen de conceptos

Se estudiará:

- Configuración del cliente.
- Dirección del proxy.
- Puerto.
- Aplicaciones.
- Política de navegación.

### Desarrollo teórico

En un **proxy explícito**, el cliente conoce la existencia del proxy y está configurado para utilizarlo.

Por ejemplo:

```text
Proxy:
IP: 192.168.10.10
Puerto: 3128
```

El cliente puede configurarse para utilizar:

```text
192.168.10.10:3128
```

La comunicación sería:

```text
Cliente
   |
   | Solicitud al proxy
   v
192.168.10.10:3128
   |
   v
Internet
```

Este modelo permite controlar directamente qué aplicaciones utilizan el proxy.

## 1.5. Proxy de caché

### Resumen de conceptos

Se estudiará:

- Caché.
- Almacenamiento temporal.
- Objetos.
- Rendimiento.
- Ancho de banda.
- Expiración.
- Actualización de contenidos.

### Desarrollo teórico

Un proxy puede almacenar determinados recursos obtenidos anteriormente en una **caché**.

Por ejemplo:

```text
Cliente 1
   |
   v
 Proxy
   |
   v
Servidor web
   |
   v
Recurso
   |
   v
 Caché
```

Posteriormente, si otro cliente solicita un recurso que puede utilizarse desde la caché:

```text
Cliente 2
   |
   v
 Proxy
   |
   v
 Caché
```

El proxy puede proporcionar el recurso sin necesidad de solicitarlo nuevamente al servidor externo, siempre que las condiciones de caché lo permitan.

Esto puede reducir:

- Consumo de ancho de banda.
- Número de solicitudes externas.
- Tiempo necesario para obtener determinados recursos.

La caché debe gestionarse correctamente porque los contenidos almacenados pueden quedar obsoletos.

# 3. Configuración del almacenamiento en la caché de un «proxy»

## Resumen de conceptos

Se estudiará:

- Caché.
- Almacenamiento temporal.
- Objetos.
- Tamaño de caché.
- Espacio de disco.
- Expiración.
- HIT.
- MISS.
- Rendimiento.

## Desarrollo teórico

La **caché** permite almacenar temporalmente determinados recursos obtenidos desde servidores externos.

El objetivo es poder reutilizar posteriormente esos recursos cuando las condiciones lo permitan.

```text
PRIMERA SOLICITUD

Cliente
   |
   v
Proxy
   |
   v
Servidor web
   |
   v
Recurso
   |
   +----> Caché
```

Posteriormente:

```text
SEGUNDA SOLICITUD

Cliente
   |
   v
Proxy
   |
   v
Caché
   |
   v
Recurso
```

Cuando un recurso puede obtenerse desde la caché hablamos conceptualmente de un **HIT**.

Cuando es necesario solicitarlo al servidor externo, podemos hablar de un **MISS**.

```text
Solicitud
    |
    v
¿Está en caché?
    |
   +--- Sí ---> HIT ---> Entregar recurso
   |
   +--- No ---> MISS ---> Servidor externo
```

### Parámetros de la caché

La configuración puede incluir:

- Tamaño máximo de la caché.
- Ubicación del almacenamiento.
- Tiempo de conservación.
- Tipos de contenido.
- Política de expiración.
- Condiciones de almacenamiento.

Una caché demasiado pequeña puede reducir sus beneficios.

Una caché excesivamente grande puede consumir recursos innecesariamente.

### Contenidos obsoletos

Uno de los problemas que debe controlarse es la posibilidad de utilizar información almacenada que ya no sea válida.

Los mecanismos HTTP y las políticas del proxy permiten determinar cuándo un recurso debe considerarse válido, actualizarse o volver a solicitarse.

# 4. Configuración de filtros

## Resumen de conceptos

Se estudiará:

- Dominios.
- URL.
- IP.
- Puertos.
- Usuarios.
- Grupos.

## Desarrollo teórico

El filtrado permite determinar qué comunicaciones o recursos pueden utilizar los clientes.

Por ejemplo:

```text
                  PROXY

        +-----------------------+
        |                       |
        |  Recurso permitido    | ---> ACCESO
        |                       |
        |  Recurso bloqueado    | ---> DENEGADO
        |                       |
        +-----------------------+
```

### Filtrado por dirección IP

Puede establecerse qué redes tienen permiso para utilizar el proxy.

```text
192.168.10.0/24 ---> PERMITIDO

192.168.20.0/24 ---> DENEGADO
```

### Filtrado por dominio

Puede establecerse una política relacionada con determinados dominios.

```text
ejemplo-permitido.es ---> PERMITIDO

ejemplo-bloqueado.es ---> DENEGADO
```

### Filtrado por URL

También pueden establecerse reglas relacionadas con determinadas URL.

### Filtrado por horario

Las políticas pueden variar según la franja horaria.

Por ejemplo:

```text
08:00 - 18:00 ---> Política corporativa
18:00 - 08:00 ---> Política diferente
```

### Filtrado por usuario

Si el proxy utiliza autenticación, las políticas pueden asociarse a usuarios o grupos.

```text
Grupo administración ---> Política A

Grupo alumnos         ---> Política B

Grupo invitados       ---> Política C
```

La posibilidad concreta depende del software utilizado y de su integración con los sistemas de identidad.

# 5. Métodos de autenticación en un «proxy»

## Resumen de conceptos

Se estudiará:

- Autenticación.
- Identidad.
- Usuario.
- Contraseña.
- Grupos.
- Directorio.
- Políticas.
- Autenticación integrada.

## Desarrollo teórico

La autenticación permite que el proxy identifique al usuario que realiza una solicitud.

Sin autenticación:

```text
Cliente ---> Proxy ---> Internet
```

Con autenticación:

```text
Cliente
   |
   | Usuario + credenciales
   v
 Proxy
   |
   | Verificación
   v
Internet
```

La autenticación permite asociar las actividades registradas a una identidad.

### Usuario y contraseña

Es uno de los métodos más sencillos.

```text
Usuario: alumno01
Contraseña: ********
```

El proxy verifica las credenciales antes de permitir el acceso.

### Integración con directorios

En organizaciones puede integrarse el proxy con sistemas centralizados de identidad.

Por ejemplo:

```text
              PROXY
                |
                v
        Servicio de directorio
                |
        +-------+-------+
        |       |       |
      Usuario Usuario Usuario
```

Esto permite utilizar cuentas y grupos existentes.

### Autenticación y autorización

Es importante diferenciar:

**Autenticación**

> ¿Quién eres?

**Autorización**

> ¿Qué puedes hacer?

Por ejemplo:

```text
Usuario:
    profesor01

Autenticación:
    Correcta

Autorización:
    Acceso a determinados recursos
```

El proxy puede utilizar la identidad para aplicar diferentes políticas.

# 13. Seguridad de un servidor proxy

## Resumen de conceptos

Se estudiará:

- Hardening.
- Acceso administrativo.
- Actualizaciones.
- Restricción de clientes.
- Autenticación.
- Logs.
- Servicios.
- Proxy abierto.

## Desarrollo teórico

El servidor proxy también debe protegerse.

Algunas medidas son:

- Mantener actualizado el software.
- Utilizar autenticación.
- Restringir qué redes pueden utilizar el proxy.
- Proteger el acceso administrativo.
- Desactivar servicios innecesarios.
- Revisar las reglas.
- Monitorizar los logs.
- Realizar copias de seguridad de la configuración.

### Evitar un proxy abierto

Uno de los problemas más importantes es configurar accidentalmente un **proxy abierto**.

Un proxy abierto sería un proxy accesible por usuarios no autorizados.

```text
Internet
   |
   +---- Usuario autorizado ---> PROXY
   |
   +---- Usuario no autorizado -> PROXY
```

Esto puede provocar que el servidor sea utilizado como intermediario para comunicaciones que la organización no controla.

Por ello es fundamental limitar los clientes autorizados.

Por ejemplo:

```text
Red corporativa 192.168.10.0/24 ---> PERMITIDA

Internet -------------------------> DENEGADA
```

- Actualizaciones.

Una correcta implantación del proxy debería seguir varios principios.

Debe controlarse el espacio utilizado y las políticas de expiración.

### 14.8. Proteger la administración

El acceso administrativo debe estar limitado a usuarios autorizados.

La instalación de un proxy no consiste únicamente en instalar el software.

Es necesario:

1. Planificar la arquitectura.
2. Instalar el servidor.
3. Configurar la red.
4. Definir el puerto de escucha.
5. Establecer qué clientes pueden utilizarlo.
6. Configurar las reglas.
7. Configurar la caché cuando sea necesaria.
8. Configurar la autenticación.
9. Activar y revisar los logs.
10. Configurar los clientes.
11. Realizar pruebas.
12. Monitorizar el funcionamiento.
13. Revisar periódicamente la configuración.

El objetivo final es disponer de un **punto de control centralizado para determinadas comunicaciones**, capaz de aplicar políticas de acceso, registrar actividad, optimizar determinados recursos y facilitar la supervisión de la red.

Un proxy correctamente configurado debe complementar, y no sustituir, otros mecanismos de seguridad como los cortafuegos, IDS/IPS, antivirus, EDR, sistemas de autenticación y sistemas de monitorización.
