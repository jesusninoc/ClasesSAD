# Instalación y configuración de cortafuegos

## Introducción

El **cortafuegos o firewall** es uno de los elementos fundamentales de la seguridad de una red. Su función principal es controlar las comunicaciones que atraviesan un sistema o dispositivo de red aplicando un conjunto de reglas de seguridad.

Un cortafuegos puede situarse entre:

- Internet y una red corporativa.
- Dos redes internas.
- Una red de usuarios y una red de servidores.
- Una red corporativa y una red de invitados.
- Una red local y una red IoT.
- Un equipo y las redes externas.

El objetivo fundamental es determinar **qué comunicaciones están permitidas y cuáles deben bloquearse o registrarse**.

Un cortafuegos no debe considerarse una solución de seguridad independiente. Forma parte de una arquitectura de defensa en profundidad en la que también pueden intervenir:

- Sistemas de autenticación.
- Sistemas IDS/IPS.
- VPN.
- Proxys.
- Antivirus y EDR.
- Sistemas de monitorización.
- Segmentación.
- Sistemas de registro.
- Mecanismos de cifrado.

La configuración de un firewall debe basarse en las necesidades reales de comunicación de la organización. Una política demasiado permisiva puede aumentar la superficie de ataque, mientras que una política excesivamente restrictiva puede impedir el funcionamiento de servicios legítimos.

# 1. Concepto de cortafuegos

## Resumen de conceptos

En este apartado se estudiará:

- Qué es un cortafuegos.
- Control del tráfico.
- Filtrado.
- Reglas de seguridad.
- Tráfico entrante.
- Tráfico saliente.
- Origen y destino.
- Puertos.
- Protocolos.
- Estado de las conexiones.
- Superficie de ataque.

### Desarrollo teórico

Un **cortafuegos** es un mecanismo de seguridad encargado de controlar y filtrar comunicaciones de red según una política de seguridad previamente definida.

Conceptualmente podemos representarlo así:

```text
                    INTERNET
                        |
                        v
                 +--------------+
                 |  FIREWALL    |
                 +--------------+
                        |
                        v
                RED CORPORATIVA
```

Cuando una comunicación intenta atravesar el cortafuegos, este analiza determinados parámetros y decide qué acción aplicar.

Por ejemplo:

```text
Origen: Internet
Destino: servidor web
Protocolo: TCP
Puerto destino: 443

          |
          v

      [ FIREWALL ]

          |
          v

      PERMITIR
```

Otra comunicación podría ser:

```text
Origen: Internet
Destino: servidor interno
Protocolo: TCP
Puerto destino: 445

          |
          v

      [ FIREWALL ]

          |
          v

      BLOQUEAR
```

La decisión dependerá de las reglas configuradas.

### Elementos que puede analizar un firewall

Dependiendo del tipo de cortafuegos, pueden analizarse:

- Dirección IP de origen.
- Dirección IP de destino.
- Puerto de origen.
- Puerto de destino.
- Protocolo.
- Interfaz de entrada.
- Interfaz de salida.
- Estado de la conexión.
- Aplicación.
- Usuario.
- Identidad del dispositivo.
- Contenido de determinadas comunicaciones.

### Tráfico entrante y saliente

Un firewall puede controlar tanto el tráfico que entra en una red como el tráfico que sale.

```text
             INTERNET
                 |
        tráfico entrante
                 |
                 v
             FIREWALL
                 |
                 v
          RED CORPORATIVA
```

Pero también:

```text
          RED CORPORATIVA
                 |
        tráfico saliente
                 |
                 v
             FIREWALL
                 |
                 v
             INTERNET
```

Esto es importante porque un firewall no solamente sirve para impedir que alguien entre.

También puede utilizarse para impedir que un equipo comprometido establezca determinadas conexiones hacia el exterior.

Por ejemplo, si un equipo resulta infectado por malware, una política de salida puede impedir que contacte con determinados destinos o servicios.

# 2. Características. Funciones principales y adicionales

## Resumen de conceptos

Se explicará:

- Filtrado de tráfico.
- Control de acceso.
- Estado de conexiones.
- NAT.
- Registro.
- Alertas.
- VPN.
- QoS.
- Autenticación.
- Alta disponibilidad.
- Inspección del tráfico.
- Gestión centralizada.

### Desarrollo teórico

Un cortafuegos puede proporcionar diferentes funciones dependiendo de su tecnología y configuración.

## 2.1. Filtrado de tráfico

Es la función básica.

El firewall analiza una comunicación y determina si debe:

- Permitirse.
- Bloquearse.
- Registrarse.
- Rechazarse.
- Redirigirse.

Por ejemplo:

```text
Internet ---> Firewall ---> Servidor web

TCP/443 ---> PERMITIDO
TCP/22  ---> BLOQUEADO
TCP/23  ---> BLOQUEADO
```

---

## 2.2. Control de acceso

El firewall puede establecer qué redes, equipos o usuarios pueden acceder a determinados recursos.

Por ejemplo:

```text
Red usuarios ---> Servidor web       PERMITIDO

Red usuarios ---> Base de datos      BLOQUEADO

Administración ---> Servidor gestión PERMITIDO
```

La idea es aplicar el principio de **mínimo privilegio también a las comunicaciones**.

Un sistema debería disponer únicamente de las comunicaciones necesarias para desarrollar su función.

---

## 2.3. Inspección con estado

Los firewalls con seguimiento de estado, conocidos habitualmente como **stateful firewalls**, mantienen información sobre las conexiones.

Por ejemplo:

```text
Cliente ---> Servidor
        TCP SYN
```

El firewall registra la conexión y puede reconocer las respuestas correspondientes.

Esto permite diferenciar entre:

- Una respuesta perteneciente a una conexión legítima.
- Una conexión nueva no solicitada.

El seguimiento del estado mejora el control sobre las comunicaciones TCP y otros flujos compatibles con el mecanismo utilizado.

---

## 2.4. Registro de actividad

Un firewall puede registrar eventos como:

- Conexiones permitidas.
- Conexiones bloqueadas.
- Intentos de acceso.
- Cambios de configuración.
- Errores.
- Eventos relacionados con VPN.
- Eventos relacionados con autenticación.

Los registros son especialmente importantes para:

- Auditorías.
- Resolución de problemas.
- Investigación de incidentes.
- Detección de comportamientos anómalos.

---

## 2.5. Alertas

Algunos firewalls pueden generar alertas cuando se producen determinados eventos.

Por ejemplo:

```text
Numerosos intentos de conexión
             |
             v
         FIREWALL
             |
             v
           ALERTA
```

Las alertas pueden posteriormente integrarse con sistemas de monitorización o SIEM.

---

## 2.6. NAT

El firewall puede integrar funciones de **NAT (Network Address Translation)**.

NAT permite modificar determinadas direcciones de red al atravesar un dispositivo.

Un escenario habitual es permitir que diferentes equipos de una red privada compartan una dirección pública para acceder a Internet.

```text
PC 1 ----\
PC 2 -----+----> NAT/FIREWALL ----> INTERNET
PC 3 ----/
```

También puede utilizarse DNAT o mecanismos equivalentes para publicar determinados servicios.

---

## 2.7. VPN

Muchos dispositivos de seguridad incorporan funcionalidades VPN.

Esto permite establecer comunicaciones protegidas entre:

- Usuarios remotos y la organización.
- Diferentes sedes.
- Redes corporativas.
- Dispositivos autorizados.

```text
Usuario remoto
      |
   Internet
      |
      v
   FIREWALL
      |
      v
      VPN
      |
      v
Red corporativa
```

---

## 2.8. QoS

Algunos firewalls incorporan mecanismos de **QoS (Quality of Service)**.

La QoS permite gestionar determinados aspectos del tráfico para priorizar comunicaciones.

Por ejemplo:

```text
Videoconferencia ---> Alta prioridad

Telefonía IP -----> Alta prioridad

Navegación web ---> Prioridad normal

Descargas --------> Prioridad inferior
```

Esto puede ayudar a mantener determinados servicios funcionando correctamente cuando existe congestión.

---

## 2.9. Alta disponibilidad

En infraestructuras críticas pueden utilizarse varios firewalls para evitar que un único dispositivo se convierta en un punto único de fallo.

Por ejemplo:

```text
              INTERNET
                  |
          +-------+-------+
          |               |
          v               v
      FIREWALL A      FIREWALL B
          |               |
          +-------+-------+
                  |
             RED INTERNA
```

La configuración concreta dependerá de la tecnología utilizada, pero el objetivo general es mantener la disponibilidad del servicio ante determinados fallos.

## 3.1.1. Filtrado de paquetes de datos

### Resumen de conceptos

Se explicará:

- Paquetes.
- IP.
- TCP.
- UDP.
- Puertos.
- Reglas.
- Filtrado.
- Cabeceras.

### Desarrollo teórico

Los firewalls de **filtrado de paquetes** toman decisiones basándose principalmente en información contenida en las cabeceras de los paquetes.

Pueden analizar:

- Dirección IP origen.
- Dirección IP destino.
- Protocolo.
- Puerto origen.
- Puerto destino.
- Interfaz.

Por ejemplo:

```text
Origen: 192.168.1.0/24
Destino: 192.168.10.20
Protocolo: TCP
Puerto: 443

        |
        v

     PERMITIR
```

Su funcionamiento es relativamente sencillo y puede ser eficiente.

Sin embargo, el análisis de las cabeceras tiene limitaciones cuando se necesita comprender qué está ocurriendo a nivel de aplicación.

---

## 3.1.2. Pasarelas de nivel de aplicación

### Resumen de conceptos

Se estudiará:

- Capa de aplicación.
- Proxy.
- HTTP.
- Aplicaciones.
- Filtrado.
- Intermediación.
- Control de contenido.

### Desarrollo teórico

Las **pasarelas de nivel de aplicación** pueden analizar las comunicaciones teniendo en cuenta características del protocolo de aplicación.

Un proxy puede actuar como intermediario:

```text
Cliente
   |
   v
[ PROXY ]
   |
   v
Servidor
```

En determinados escenarios puede analizar información relacionada con protocolos como:

- HTTP.
- SMTP.
- FTP.
- DNS.

Esto permite aplicar políticas más específicas que las basadas exclusivamente en direcciones y puertos.

Por ejemplo, un proxy web puede aplicar políticas relacionadas con las solicitudes HTTP.

Una ventaja es que puede proporcionar un mayor nivel de control.

La contrapartida es que suele requerir una configuración más compleja y puede introducir un mayor consumo de recursos.

---

## 3.1.3. Pasarelas de nivel de circuitos

### Resumen de conceptos

Se explicará:

- Circuito.
- Sesión.
- Conexión.
- Intermediación.
- Nivel de transporte.
- Soluciones híbridas.

### Desarrollo teórico

Las **pasarelas de nivel de circuitos** controlan determinadas características de las conexiones sin necesidad de analizar todo el contenido de la aplicación.

Su funcionamiento se sitúa conceptualmente entre:

- El filtrado de paquetes.
- El análisis completo de la aplicación.

Pueden controlar la creación y mantenimiento de determinadas conexiones.

El objetivo es proporcionar control sobre la comunicación sin realizar necesariamente una inspección completa del contenido.

---

## 3.1.4. Cortafuegos híbridos

### Resumen de conceptos

Se estudiará:

- Combinación de tecnologías.
- Filtrado.
- Estado.
- Aplicaciones.
- Proxy.
- Inspección.
- Defensa en profundidad.

### Desarrollo teórico

En la práctica, muchas soluciones modernas combinan diferentes técnicas.

Un firewall puede utilizar simultáneamente:

- Filtrado de paquetes.
- Seguimiento de estado.
- NAT.
- VPN.
- Inspección de determinadas aplicaciones.
- IDS/IPS.
- Registro.
- Control de usuarios.

Por eso es habitual hablar de soluciones **híbridas** o de dispositivos de seguridad multifunción.

Conceptualmente:

```text
                 FIREWALL
                     |
        +------------+------------+
        |            |            |
    Filtrado       NAT          VPN
        |            |            |
        +------------+------------+
                     |
                  IDS/IPS
                     |
                 Registros
```

# 3.3. Cortafuegos software vs. equipos hardware específicos

## Resumen de conceptos

Se estudiará:

- Firewall software.
- Firewall hardware.
- Firewall virtual.
- Rendimiento.
- Administración.
- Coste.
- Escalabilidad.
- Seguridad.

### Desarrollo teórico

Los firewalls pueden implementarse mediante software o mediante dispositivos específicamente diseñados para funciones de seguridad.

### Firewall software

Se ejecuta sobre un sistema operativo.

Puede instalarse en:

- Ordenadores.
- Servidores.
- Máquinas virtuales.
- Equipos de seguridad.

Ventajas:

- Flexibilidad.
- Facilidad para realizar determinadas configuraciones.
- Puede aprovechar hardware existente.
- Puede proteger directamente un servidor o equipo.

Limitaciones:

- Depende del sistema operativo.
- Consume recursos del equipo.
- Una mala configuración del sistema puede afectar a la seguridad.

### Firewall hardware

Es un dispositivo dedicado o especializado.

Puede incluir:

- Interfaces de red.

# 4.5. Reglas de filtrado de cortafuegos

## Resumen de conceptos

Se estudiará:

- Origen.
- Destino.
- Protocolo.
- Puerto.
- Acción.
- Orden de las reglas.
- Prioridad.
- Registro.

### Desarrollo teórico

Una regla de firewall puede representarse conceptualmente mediante:

```text
ORIGEN | DESTINO | PROTOCOLO | PUERTO | ACCIÓN
```

Por ejemplo:

```text
Internet | Web DMZ | TCP | 443 | PERMITIR
Internet | Red LAN | TCP | ANY | BLOQUEAR
LAN      | Internet | TCP | 443 | PERMITIR
```

Una regla puede incorporar también:

- Horarios.
- Usuarios.
- Interfaces.
- Aplicaciones.
- Países o regiones, cuando el producto lo permita.
- Identidad del dispositivo.
- Estado de conexión.

### Orden de las reglas

En muchos firewalls las reglas se evalúan siguiendo un orden determinado.

Por ejemplo:

```text
Regla 1 -> PERMITIR HTTPS
Regla 2 -> BLOQUEAR Internet -> LAN
Regla 3 -> PERMITIR LAN -> Internet
Regla final -> BLOQUEAR
```

Una regla demasiado amplia situada antes de una regla específica puede hacer que esta última nunca se aplique.

Por eso es importante comprender el funcionamiento concreto del firewall utilizado.

### Documentación

Las reglas deberían estar documentadas.

Por ejemplo:

```text
Regla: FW-001
Origen: Internet
Destino: Servidor Web DMZ
Servicio: HTTPS
Acción: Permitir
Motivo: Publicación del sitio web
Registro: Activado
```

Esto facilita las auditorías y el mantenimiento.

# 11. Principios para diseñar las reglas de un cortafuegos

## Resumen de conceptos

Se estudiará:

- Mínimo privilegio.
- Denegar por defecto.
- Permitir lo necesario.
- Segmentación.
- Documentación.
- Registro.
- Revisión.
- Simplicidad.

### Desarrollo teórico

Una buena configuración de firewall debe basarse en una política de seguridad claramente definida.

Algunos principios importantes son:

### 1. Denegar lo que no sea necesario

No debería existir exposición innecesaria.

### 2. Permitir únicamente lo necesario

Si un servidor solamente necesita HTTPS, no es necesario publicar todos sus puertos.

### 3. Separar las redes

No todos los sistemas deberían encontrarse en la misma zona.

### 4. Aplicar mínimo privilegio

Una comunicación solamente debe estar permitida cuando exista una necesidad legítima.

### 5. Registrar los eventos relevantes

Los bloqueos y accesos importantes pueden ser necesarios para la investigación.

### 6. Documentar las reglas

Cada regla debería tener un motivo.

### 7. Revisar periódicamente

Las necesidades de una organización cambian.

### 8. Evitar reglas excesivamente generales

Una regla demasiado amplia puede permitir más tráfico del necesario.

# 12. Errores habituales en la configuración de un firewall

## Resumen de conceptos

Se analizarán:

- Reglas demasiado permisivas.
- Servicios innecesarios.
- Falta de registros.
- Configuración incorrecta.
- Reglas obsoletas.
- Administración insegura.
- Falta de pruebas.
- Ausencia de copias de seguridad.

### Desarrollo teórico

Algunos problemas habituales son:

### Permitir todo el tráfico

Una política excesivamente permisiva reduce considerablemente la utilidad del firewall.

### Publicar servicios innecesarios

Cada servicio publicado aumenta la superficie de exposición.

### No registrar eventos

Si no se generan registros adecuados, investigar determinados incidentes puede resultar más complicado.

### Mantener reglas antiguas

Una regla que ya no es necesaria puede crear una exposición innecesaria.

### Permitir acceso administrativo desde cualquier lugar

Las interfaces de administración deberían estar especialmente protegidas.

### No probar las reglas

Una configuración que parece correcta puede no comportarse como se esperaba.

### No realizar copias de seguridad

La configuración del firewall debe poder recuperarse ante un fallo o una configuración incorrecta.

- Por qué la configuración debe mantenerse y revisarse.

### Desarrollo teórico

El firewall debe entenderse como un **punto de control de las comunicaciones**, no simplemente como una barrera que separa Internet de una red interna.

Una arquitectura completa puede representarse mediante:

```text
                           INTERNET
                               |
                               v
                        +-------------+
                        |  FIREWALL   |
                        +-------------+
                          /    |     \
                         /     |      \
                       NAT    VPN    IDS/IPS
                         |     |       |
                         +-----+-------+
                               |
                               v
                              DMZ
                         /     |     \
                        /      |      \
                      WEB     MAIL    DNS
                               |
                               v
                       FIREWALL INTERNO
                               |
                               v
                        RED CORPORATIVA
                       /      |       \
                      /       |        \
                 USUARIOS SERVIDORES   IoT
                     |        |          |
                     v        v          v
                    EDR      EDR        EDR
                      \        |        /
                       \       |       /
                        +------+------+
                               |
                               v
                              SIEM
```

El funcionamiento correcto depende de que todos estos elementos estén coordinados.

La idea fundamental puede resumirse como:

```text
Identificar las comunicaciones necesarias
                    +
             Diseñar las reglas
                    +
          Denegar lo innecesario
                    +
        Permitir lo estrictamente necesario
                    +
             Registrar eventos
                    +
            Realizar pruebas
                    +
        Revisar periódicamente
                    =
        Firewall correctamente gestionado
```

Un cortafuegos correctamente instalado pero mal configurado puede proporcionar una falsa sensación de seguridad.

Por eso la seguridad debe comenzar antes de la instalación, mediante el análisis de las necesidades de comunicación, y continuar después de la instalación mediante:

- Pruebas.
- Monitorización.
- Revisión de reglas.
- Actualizaciones.
- Auditorías.
- Análisis de logs.
- Copias de seguridad.
- Integración con otros mecanismos de seguridad.

La finalidad no es bloquear todas las comunicaciones, sino **permitir las comunicaciones legítimas necesarias y dificultar o impedir las que no deberían producirse**.

El firewall constituye así una pieza fundamental dentro de una arquitectura de **defensa en profundidad**, pero debe trabajar conjuntamente con la segmentación, la autenticación, el cifrado, los sistemas IDS/IPS, los mecanismos de protección de endpoints, la monitorización y los procedimientos de respuesta ante incidentes.
