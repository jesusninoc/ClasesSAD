# Implantación de seguridad perimetral

## Introducción

La **seguridad perimetral** comprende el conjunto de mecanismos destinados a controlar, filtrar, proteger y supervisar las comunicaciones entre diferentes redes o zonas de seguridad.

Tradicionalmente se ha utilizado para proteger una red interna frente a redes externas consideradas menos confiables, especialmente Internet.

La seguridad perimetral puede incluir diferentes elementos:

- Cortafuegos.
- Sistemas bastión.
- Proxys.
- VPN.
- Sistemas IDS/IPS.
- Routers y dispositivos de filtrado.
- Segmentación de redes.
- Zonas desmilitarizadas o DMZ.
- Sistemas de monitorización.

La idea fundamental es establecer **puntos de control entre diferentes zonas de confianza**.

Por ejemplo:

```text
Internet
   |
   v
[ Cortafuegos ]
   |
   v
[ Red corporativa ]
```

Sin embargo, una arquitectura moderna no debe depender exclusivamente de un único perímetro. Una organización puede disponer de diferentes zonas con distintos niveles de confianza y controles específicos.

## 1.1. Perímetro de red

### Resumen de conceptos

Se hablará de:

- Red interna.
- Red externa.
- Internet.
- Zona de confianza.
- Punto de control.
- Filtrado.
- Segmentación.

### Desarrollo teórico

El **perímetro de red** puede entenderse como la frontera lógica entre diferentes zonas de una infraestructura.

Un ejemplo sencillo sería la separación entre:

- Internet.
- Red corporativa.
- Servidores.
- Equipos de usuarios.

El objetivo del perímetro es establecer mecanismos de control entre esas zonas.

Por ejemplo:

```text
                 INTERNET
                     |
                     v
              [ CORTAFUEGOS ]
                     |
          +----------+----------+
          |                     |
          v                     v
       [ DMZ ]           [ RED INTERNA ]
          |                     |
          v                     v
      Servidores              Usuarios
```

El perímetro permite establecer reglas como:

> Desde Internet se permite acceder al servidor web de la DMZ.

Pero:

> Desde Internet no se permite acceder directamente a los equipos internos.

Esta separación permite reducir la superficie de exposición.

## 1.2. Sistemas bastión

### Resumen de conceptos

Se estudiará:

- Host bastión.
- Sistema endurecido.
- Punto de entrada.
- Hardening.
- Servicios expuestos.
- Monitorización.
- Administración segura.

### Desarrollo teórico

Un **sistema bastión** es un equipo especialmente protegido que se utiliza como punto controlado de acceso a determinados servicios o redes.

La idea fundamental es que el sistema bastión debe estar **endurecido o bastionado**.

Esto implica reducir al mínimo las posibilidades de ataque.

Entre las medidas que pueden aplicarse se encuentran:

- Instalar únicamente los servicios necesarios.
- Desactivar servicios innecesarios.
- Mantener el sistema actualizado.
- Aplicar reglas de firewall.
- Utilizar autenticación robusta.
- Registrar las conexiones.
- Monitorizar la actividad.
- Limitar los usuarios autorizados.
- Aplicar el principio de mínimo privilegio.

Por ejemplo, una organización podría utilizar un servidor bastión para permitir la administración de determinados sistemas internos.

En lugar de permitir:

```text
Internet ---> Servidor interno
```

podría establecer:

```text
Internet ---> Bastión ---> Servidor interno
```

El bastión se convierte así en un punto controlado de acceso.

## 1.3. Cortafuegos

### Resumen de conceptos

Se explicará:

- Firewall.
- Filtrado.
- Reglas.
- IP.
- Puertos.
- Protocolos.
- Origen.
- Destino.
- Tráfico entrante.
- Tráfico saliente.
- Stateful firewall.

### Desarrollo teórico

Un **cortafuegos o firewall** es un mecanismo utilizado para controlar el tráfico de red de acuerdo con determinadas reglas.

Puede decidir si una comunicación debe:

- Permitirse.
- Bloquearse.
- Registrarse.
- Redirigirse.

Las reglas pueden tener en cuenta diferentes características:

- Dirección IP de origen.
- Dirección IP de destino.
- Puerto de origen.
- Puerto de destino.
- Protocolo.
- Interfaz.
- Estado de la conexión.

Por ejemplo:

```text
Internet
   |
   v
[ FIREWALL ]
   |
   +---- Puerto 443 ----> Servidor web
   |
   +---- Puerto 22 -----> BLOQUEADO
```

Una regla podría permitir HTTPS hacia un servidor web y bloquear el acceso externo a otros servicios.

### Principio de mínimo privilegio aplicado a la red

La idea de mínimo privilegio también puede aplicarse al tráfico.

No debería permitirse todo el tráfico por defecto si solamente son necesarios determinados servicios.

Una política puede plantearse como:

> Permitir únicamente las comunicaciones necesarias y bloquear el resto.

También es importante registrar determinados eventos para poder investigar posteriormente qué comunicaciones se produjeron.

## 1.4. Proxys

### Resumen de conceptos

Se estudiará:

- Proxy.
- Cliente.
- Servidor.
- Intermediario.
- Control de acceso.
- Filtrado.
- Caché.
- Registro.
- Proxy directo.
- Proxy inverso.

### Desarrollo teórico

Un **proxy** actúa como intermediario entre dos partes de una comunicación.

En lugar de que el cliente contacte directamente con el servidor:

```text
Cliente ---> Servidor
```

la comunicación puede realizarse mediante:

```text
Cliente ---> Proxy ---> Servidor
```

El proxy puede aplicar diferentes funciones:

- Control de acceso.
- Filtrado.
- Registro.
- Caché.
- Aplicación de políticas.
- Ocultación de determinados detalles de la infraestructura.

### Proxy directo

Un **forward proxy** se sitúa entre los clientes y los servidores externos.

```text
Usuario
   |
   v
Proxy
   |
   v
Internet
```

Puede utilizarse para controlar las conexiones realizadas desde una red corporativa.

### Proxy inverso

Un **reverse proxy** se sitúa delante de servidores.

```text
Internet
   |
   v
Reverse Proxy
   |
   +----> Servidor web 1
   |
   +----> Servidor web 2
```

Puede utilizarse junto con:

- Servidores web.
- Balanceadores.
- Sistemas de protección.
- Terminación TLS.
- Control de acceso.

La diferencia fundamental que debe recordar el alumnado es:

> El proxy directo representa principalmente a los clientes.

> El proxy inverso representa principalmente a los servidores.

## 1.5. VPN

### Resumen de conceptos

Se hablará de:

- VPN.
- Túnel.
- Cifrado.
- Autenticación.
- Confidencialidad.
- Integridad.
- Acceso remoto.
- Interconexión de redes.
- IPsec.
- TLS.

### Desarrollo teórico

Una **VPN (Virtual Private Network)** permite establecer una comunicación protegida a través de una infraestructura de red que puede no ser confiable.

Conceptualmente:

```text
Red A
  |
  |==== TÚNEL VPN ====|
  |                   |
  v                   v
Internet             Red B
```

La VPN puede proporcionar diferentes mecanismos de seguridad, dependiendo de la tecnología utilizada:

- Autenticación.
- Confidencialidad.
- Integridad.

Uno de sus usos habituales es permitir que un usuario remoto pueda acceder a recursos corporativos.

Por ejemplo:

```text
Empleado
   |
Internet
   |
   v
[ VPN ]
   |
   v
Red corporativa
```

También puede utilizarse para conectar diferentes sedes:

```text
Sede A
   |
   |==== VPN ====|
                |
              Sede B
```

Es importante explicar que una VPN **no convierte automáticamente una red en segura**. La seguridad depende de la tecnología utilizada, su configuración, las credenciales, las políticas de acceso y los sistemas que quedan disponibles una vez establecida la conexión.

## 1.6. IDS e IPS dentro de la seguridad perimetral

### Resumen de conceptos

Se estudiará:

- IDS.
- IPS.
- Detección.
- Prevención.
- Alertas.
- Bloqueo.
- Monitorización.
- Tráfico sospechoso.

### Desarrollo teórico

Los sistemas **IDS (Intrusion Detection System)** e **IPS (Intrusion Prevention System)** pueden integrarse en una arquitectura de seguridad perimetral.

Un IDS analiza determinadas actividades y genera alertas cuando identifica comportamientos sospechosos.

Un IPS puede además actuar para bloquear determinados comportamientos.

Podemos representar la diferencia:

```text
IDS:

Tráfico ---> IDS ---> Alerta
```

Mientras que:

```text
IPS:

Tráfico ---> IPS ---> Bloqueo
```

Estos sistemas pueden complementar al firewall.

Por ejemplo:

```text
Internet
   |
   v
[ Firewall ]
   |
   v
[ IDS/IPS ]
   |
   v
[ DMZ / Red interna ]
```

Cada mecanismo cumple una función diferente.

## 2.1. Arquitectura débil de subred protegida

### Resumen de conceptos

Se explicará:

- Subred protegida.
- Firewall.
- Red externa.
- Red interna.
- Punto único de control.
- Limitaciones.
- Superficie de ataque.

### Desarrollo teórico

Una arquitectura de **subred protegida débil** utiliza un número reducido de mecanismos para separar la red interna de la red externa.

Un esquema conceptual simplificado sería:

```text
                 INTERNET
                     |
                     v
               [ FIREWALL ]
                     |
                     v
               RED INTERNA
```

En esta arquitectura existe un único punto principal de separación.

La ventaja es su sencillez.

Sin embargo, presenta determinadas limitaciones.

Si el firewall se configura incorrectamente o un servicio interno queda comprometido, la separación entre las diferentes zonas puede ser insuficiente.

Por ejemplo:

```text
Internet
   |
Firewall
   |
Servidor web
   |
Red interna
```

Si el servidor web resulta comprometido y se encuentra directamente dentro de la red interna, el atacante podría intentar utilizar ese sistema como punto de partida para acceder a otros recursos.

Por ello se utilizan arquitecturas con una separación mayor.

- Defensa en profundidad.

### Desarrollo teórico

Una arquitectura fuerte introduce **más controles y separación entre las diferentes zonas de la infraestructura**.

Un ejemplo conceptual podría ser:

```text
                  INTERNET
                      |
                      v
                [ FIREWALL 1 ]
                      |
                      v
                    DMZ
                      |
                [ FIREWALL 2 ]
                      |
                      v
                 RED INTERNA
```

En este diseño, los servidores que deben ser accesibles desde Internet pueden situarse en una zona intermedia.

La red interna queda separada de la DMZ mediante otro mecanismo de control.

Esto permite establecer políticas diferentes.

Por ejemplo:

```text
Internet ---> DMZ
              |
              | acceso limitado
              v
          Red interna
```

Si un servidor de la DMZ resulta comprometido, el atacante todavía tiene que superar los controles existentes para acceder a la red interna.

Este concepto está directamente relacionado con la **defensa en profundidad**.

## 2.4. Zonas desmilitarizadas DMZ

### Resumen de conceptos

Se estudiará:

- DMZ.
- Servidores públicos.
- Red interna.
- Internet.
- Segmentación.
- Firewall.
- Políticas de acceso.
- Servicios expuestos.

### Desarrollo teórico

Una **DMZ (Demilitarized Zone)** es una zona de red situada entre redes con diferentes niveles de confianza.

Uno de sus usos más habituales es alojar servicios que deben ser accesibles desde Internet sin situarlos directamente dentro de la red interna.

Por ejemplo:

```text
                    INTERNET
                        |
                        v
                  [ FIREWALL ]
                        |
                        v
                       DMZ
                 /       |       \
                /        |        \
           Web       Mail       DNS
                \        |        /
                 \       |       /
                        |
                  [ FIREWALL ]
                        |
                        v
                  RED INTERNA
```

En este escenario:

- Internet puede acceder a determinados servicios de la DMZ.
- Los usuarios internos pueden acceder a servicios de la DMZ.
- La DMZ tiene controles de acceso hacia la red interna.
- La red interna no queda directamente expuesta a Internet.

### Ejemplo

Supongamos una empresa que dispone de:

- Servidor web.
- Servidor de correo.
- Base de datos.
- Equipos de empleados.

Una posible arquitectura sería:

```text
Internet
   |
   v
Firewall
   |
   v
DMZ
   |
   +---- Servidor web
   |
   +---- Servidor de correo
   |
   v
Firewall interno
   |
   v
Red corporativa
   |
   +---- Equipos
   |
   +---- Base de datos
```

El servidor web puede necesitar aceptar conexiones desde Internet.

La base de datos, en cambio, podría no necesitar ninguna conexión directa desde Internet.

Esta separación reduce la superficie de ataque.

## 2.5. Arquitectura con DMZ de dos cortafuegos

### Resumen de conceptos

Se estudiará:

- Dos cortafuegos.
- DMZ.
- Perímetro externo.
- Perímetro interno.
- Segmentación.
- Flujo de tráfico.

### Desarrollo teórico

Una arquitectura habitual consiste en utilizar dos dispositivos de filtrado alrededor de la DMZ.

```text
                  INTERNET
                      |
                      v
                [ FIREWALL 1 ]
                      |
                      v
                     DMZ
                      |
                [ FIREWALL 2 ]
                      |
                      v
                RED INTERNA
```

El primer firewall controla el tráfico entre Internet y la DMZ.

El segundo controla el tráfico entre la DMZ y la red interna.

Esto permite aplicar políticas diferentes en cada frontera.

Por ejemplo:

```text
Internet ---> Web DMZ       Permitido
Internet ---> Red interna   Bloqueado

DMZ ---> Base de datos      Solo necesario
DMZ ---> Equipos usuarios   Bloqueado

Red interna ---> DMZ        Según política
```

La finalidad no es simplemente añadir dispositivos, sino **crear diferentes zonas de seguridad con reglas específicas**.

```text

    VLAN 10         VLAN 20        VLAN 30
```

La separación lógica permite aplicar políticas diferentes.

Una organización puede disponer de una red específica para visitantes:


La red de invitados debería estar separada de los recursos internos.

```text
              |        |        |
             IoT      IoT      IoT
```

Esto permite limitar las comunicaciones de dispositivos que pueden presentar unas características de seguridad diferentes a las de los equipos corporativos.

Los usuarios remotos pueden acceder mediante una VPN:

```text
Usuario remoto
      |
   Internet
      |
      v
     VPN
      |
      v

```

La VPN debe integrarse con mecanismos de:

- Autenticación.
- Control de acceso.
- Segmentación.
- Monitorización.
- Registro.

# 3. Principios fundamentales de la seguridad perimetral

## Resumen de conceptos

La idea global del bloque es:

- Reducir la superficie de ataque.
- Separar redes.
- Controlar comunicaciones.
- Aplicar mínimo privilegio.
- Crear diferentes zonas de confianza.
- Monitorizar.
- Detectar.
- Responder.
- Evitar depender de un único mecanismo.

### Desarrollo teórico

La seguridad perimetral no debe entenderse simplemente como:

> "Instalar un firewall entre Internet y la red."

Una arquitectura de seguridad perimetral debe responder a varias preguntas:

### ¿Qué queremos proteger?

Por ejemplo:

- Usuarios.
- Servidores.
- Aplicaciones.
- Bases de datos.
- Dispositivos IoT.
- Información.

### ¿Quién necesita acceder?

Debe determinarse qué usuarios, equipos o servicios necesitan comunicación.

### ¿Desde dónde?

No es lo mismo permitir acceso desde:

- Internet.
- Red corporativa.
- VPN.
- DMZ.
- Red de administración.

### ¿A qué servicio?

Debe especificarse el recurso concreto.

### ¿Qué protocolo y puerto necesita?

La política debe ser lo más específica posible.

### ¿Qué ocurre si un sistema resulta comprometido?

Aquí aparece la importancia de la segmentación.

Por ejemplo:

```text
                 INTERNET
                     |
                FIREWALL
                     |
                     v
                    DMZ
               /           \
              /             \
         Servidor web    Servidor correo
              |
         FIREWALL INTERNO
              |
              v
         RED CORPORATIVA
          /          \
       Usuarios    Servidores
                     |
                Red de datos
```

Si el servidor web es comprometido, el objetivo es que el atacante no pueda acceder automáticamente a toda la infraestructura.

# 4. Relación entre seguridad perimetral y defensa en profundidad

## Resumen de conceptos

Se relacionarán:

- Firewall.
- Proxy.
- VPN.
- DMZ.
- IDS/IPS.
- Segmentación.
- Bastionado.
- Monitorización.
- Mínimo privilegio.
- Defensa en profundidad.

### Desarrollo teórico

Los diferentes elementos de seguridad perimetral deben trabajar conjuntamente.

Una arquitectura podría incluir:

```text
                         INTERNET
                             |
                             v
                      [ FIREWALL ]
                             |
                             v
                          [ PROXY ]
                             |
                             v
                            DMZ
                       /             \
                      /               \
               [ IDS/IPS ]       Servidores
                      |
                      v
                [ FIREWALL ]
                      |
                      v
                RED CORPORATIVA
                 /           \
                /             \
           Usuarios         Servidores
                |                 |
                v                 v
               EDR              Datos
```

Cada mecanismo tiene una función:

| Mecanismo | Función principal |
|---|---|
| Firewall | Controlar y filtrar tráfico |
| Proxy | Actuar como intermediario y aplicar políticas |
| VPN | Crear comunicaciones protegidas |
| Bastión | Proporcionar un punto controlado de acceso |
| DMZ | Separar servicios expuestos de la red interna |
| IDS | Detectar actividades sospechosas |
| IPS | Detectar y bloquear determinadas actividades |
| Segmentación | Limitar la comunicación entre zonas |
| Monitorización | Observar y registrar actividad |
| EDR | Detectar y responder ante amenazas en los equipos |

La seguridad perimetral se convierte así en un conjunto de controles que trabajan de forma coordinada.

# 5. Idea global para explicar al alumnado

## Resumen de conceptos

Al terminar este bloque el alumnado debería comprender:

- Qué es un perímetro de red.
- Para qué sirve un firewall.
- Qué función tiene un proxy.
- Qué es una VPN.
- Qué es un sistema bastión.
- Qué es una DMZ.
- Por qué se segmentan las redes.
- Diferencias entre arquitecturas débiles y fuertes.
- Cómo se protegen los servicios expuestos.
- Por qué no debe existir un único mecanismo de seguridad.
- Cómo aplicar defensa en profundidad.

### Desarrollo teórico

La idea fundamental puede resumirse mediante una arquitectura:

```text
                           INTERNET
                               |
                               v
                         [ FIREWALL ]
                               |
                               v
                            [ PROXY ]
                               |
                               v
                              DMZ
                    +----------+----------+
                    |          |          |
                    v          v          v
                  WEB        MAIL        DNS
                    |          |          |
                    +----------+----------+
                               |
                         [ FIREWALL ]
                               |
                               v
                        RED CORPORATIVA
                         /             \
                        /               \
                       v                 v
                  USUARIOS           SERVIDORES
                       |                 |
                       v                 v
                      EDR              DATOS
```

El objetivo no es conseguir que ningún ataque pueda producirse, sino **reducir la exposición, controlar las comunicaciones, limitar los movimientos del atacante y aumentar la capacidad de detección y respuesta**.

Una arquitectura perimetral debe aplicar el principio de **mínimo privilegio también a las comunicaciones**.

Si un servidor solamente necesita comunicarse con otro servidor mediante un determinado protocolo, no debería disponer de acceso ilimitado a toda la red.

La misma filosofía se aplica a los usuarios, los dispositivos IoT, las redes de invitados y los sistemas de administración.

Por tanto:

```text
Menor exposición
       +
Segmentación
       +
Control de acceso
       +
Monitorización
       +
Defensa en profundidad
       =
Mayor capacidad de protección
```

La seguridad perimetral debe integrarse con el resto de mecanismos de seguridad de la organización.

Un firewall puede controlar el tráfico, pero no sustituye al bastionado de los servidores, la autenticación, las actualizaciones, el cifrado, la monitorización, los sistemas de detección ni las copias de seguridad.

El objetivo final es construir una infraestructura en la que **cada zona tenga únicamente las comunicaciones necesarias y cada mecanismo de seguridad aporte una capa adicional de protección**.
